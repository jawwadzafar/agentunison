- **Does it generalize?** Partially. The projection *mechanics* (capability matrix → adapter → validator → installer, CI drift gate, real-CLI smoke) generalize. 4. **Files read.** `<project>/.agents-skills-sync.json` (`src/lib/project-config.ts:19`); the content source's `<sourceRoot>/` subtree only (`src/lib/local-source.ts:41-42`: "Anything outside <sourceRoot> is ignored — the engine only owns that subtree"); existing `.gitignore` (`src/gitignore.ts:126`); `lstat`/`readlink` of target paths to classify (`src/reconciler.ts:31-51`). It never parses SKILL.md/frontmatter/settings — content is opaque bytes.
5. **Symlinks?** Yes, always, absolute-path symlinks into staging: `Deno.symlink(linkTarget, linkPath)` with `stagingEntry = join(stagingRoot, …)` (`src/reconciler.ts:65-68, 100, 105`). Ownership test is `linkTarget.startsWith(stagingPrefix)` (`src/reconciler.ts:47`). No fallback when symlinks are unavailable.
6. **Copy vs symlink.** Symlink by design: "Symlinks, not copies. One source of truth per machine per project. Copies would drift; symlinks make drift impossible at rest" (`docs/IMPLEMENTATION.md:410`). The *staging* dir itself is a copy (tarball extract or `Deno.copyFile` walk, `src/lib/local-source.ts:57-73`) made read-only after an atomic swap so edits-through-symlink EACCES loudly (`src/sync.ts:97-103`, `docs/IMPLEMENTATION.md:415`).
7. **Existing-file handling.** Five-way classification `missing | own-symlink | foreign-symlink | real-file | real-dir` (`src/reconciler.ts:14, 31-51`). `missing` → link; `own-symlink` → relink; anything else → **quarantine then link** (never overwrite in place), or `--force-collisions` → `Deno.remove(recursive)` then link (`src/reconciler.ts:104-125`). Decision table in `docs/IMPLEMENTATION.md:214-220`. A shared file the upstream stops shipping: own-symlink removed, "anything else (real file, foreign symlink) untouched — it's not ours" (`src/reconciler.ts:236-244`).
8. **Collision detection.** Purely path-level: a staging entry whose project path is occupied by something not pointing into staging (`src/reconciler.ts:115`). No name-collision detection *across* categories, tools, or content semantics (e.g., two skills with same `name:` frontmatter) — the engine does not read content.
9. **Quarantine.** `<project>/<category.projectPath>/<profile.quarantineDir>/<name>.<ISO-timestamp>` via `Deno.rename` (`src/reconciler.ts:53-63`; e.g. `.claude/skills/.claude-config-collisions/legacy-thing.2026-05-18T12-00-00-000Z/`). Shared-file quarantine at `<project>/<sourceRoot>/<quarantineDir>/` (`src/reconciler.ts:264`). Pruned after `kQuarantineTtlDays = 30` by mtime (`src/reconciler.ts:11, 160-184`). The quarantine dir is itself added to the managed gitignore block (`src/gitignore.ts:231, 247-251`). Preserved on unenroll (`src/unenroll.ts:1-3`, `README.md:158`).
10. **Dry-run.** `--dry-run [--project]`: read-only planner producing `would-symlink | would-refresh | would-quarantine(reason)` per category plus a `+/-` gitignore-block diff (`src/dry-run.ts:23-26, 156-186`). Header promise "No mutations will occur." (`src/dry-run.ts:209`). **Gaps**: it plans categories but *not shared files* (`planCategory` only, `src/dry-run.ts:157`), cannot plan when staging is missing ("cannot predict without extracting", `:150`), and for local sources only sanity-checks the path (`:212-225`). Integration test `--dry-run does not mutate project or config` (`tests/integration/enroll-and-sync.test.ts:454`).
11. **Idempotency.** Fast path: if `fetchKey === project.lastSha` and per-file SHA-256 map of staging still matches `contentHashes`, return `up-to-date` (`src/sync.ts:227-231, 140-166`; `src/lib/hashes.ts:51-127`). Re-run always re-creates own-symlinks (`src/reconciler.ts:109-113`) and rewrites the gitignore block deterministically (sorted entries, `src/gitignore.ts:229`). `--enroll --if-needed` is a no-op when enrolled (`src/enroll.ts:208-211`). Registry writes are temp+rename under flock (`src/registry.ts:87-96`, `src/lock.ts`). Project id = `sha1(realpath).slice(0,8)` — deterministic, but moving the dir changes identity (`docs/IMPLEMENTATION.md:92`).
12. **Reverse adoption.** None. There is no path to ingest a project's existing `.claude/skills/*` back into the content repo; a pre-existing real skill with a colliding name is quarantined (`src/reconciler.ts:122-125`), and non-colliding project-local files are simply left in place ("project-added file survives sync", `tests/integration/enroll-and-sync.test.ts:484`).
13. **Drift prevention.** Three mechanisms: (a) read-only staging (`src/sync.ts:102`); (b) per-file SHA-256 verification each tick — mismatch forces re-materialize, and a self-check right after extract with one retry then `Drift` exit 4 (`src/sync.ts:111-138`, `src/lib/hashes.ts:82-127`); (c) `--check` exit 4 on upstream-SHA or content drift, exit 5 on damaged gitignore block (`src/status.ts:346-407`; `src/types.ts:33-40`); cron tick + sentinel `state/sync-status` + OS notification only on state *transition* (`docs/IMPLEMENTATION.md:200-206`). Gitignore block is strictly validated (exactly one BEGIN/END pair, `src/gitignore.ts:58-92`), with a relaxed `--repair-gitignore` path (`:94-114, 164-178`).
14. **Adapter generation / format translation.** None. Profiles only remap *paths*: `CategoryDef{sourcePath, projectPath}` (`src/types.ts:71-75`), e.g. codex `.agents/skills` → `.agents/skills`, `rules` → `.codex/rules` (`src/types.ts:102-112`). Content bytes are identical across tools; the content repo must hold a separate `.claude/` and `.codex/` subtree (`README.md:18-43`). Categories are hard-coded per profile — "adding a brand-new category (e.g. `.claude/agents/`) requires editing the profile in this engine" (`README.md:47`; `docs/PROFILES.md:22`).
15. **Generated artifacts committed vs ignored.** Ignored, by construction: every symlink and quarantine dir is written into a managed `# BEGIN claude-config (do not edit manually)` … `# END claude-config` block in `<root>/.gitignore` (`src/gitignore.ts:17-22`); the consumer commits only the empty marker stub + `.agents-skills-sync.json` + postinstall script (`docs/PRODUCT-REPO-INTEGRATION.md:43-140`). Codex gets two blocks (`.agents/.gitignore`, `.codex/.gitignore`) (`src/types.ts:109`).
16. **Real-harness tests vs structural.** Structural/filesystem only. Integration tests spawn the compiled CLI against a temp project and a mocked GitHub tarball server, then assert symlinks, gitignore, sentinel, exit codes (`CLAUDE.md:11`; `tests/integration/enroll-and-sync.test.ts:186-994`). Nothing ever invokes `claude` or `codex` to prove a skill is discovered. The Codex path claim ("`.agents/skills/` … the path Codex CLI actually scans", `src/types.ts:99-101`) is asserted, not tested.
17. **Uninstall/reverse.** `--unenroll`: removes only symlinks whose target starts with the staging dir, removes the managed gitignore blocks, deletes staging, removes registry entry; preserves project-added files and quarantine (`src/unenroll.ts:21-62, 117-127`); interactive preflight summary + confirm (`:74-115`). Separate `agents-skills-sync-uninstall` binary unenrolls everything, unregisters cron by exact binary path, removes cache/state/bin; `--purge` for token+registry (`src/uninstall.ts:2-4, 67-101`).
18. **Windows breakage.** Not supported at all: `bootstrap.sh:63-66` dies on anything but Darwin/Linux; `df -kP` and `tar` are shelled (`src/lib/fs-utils.ts:36-41, 94-101`); POSIX mode bits `0o555/0o444` (`:155-163`); `flock` via `Deno.FsFile.lock` (`src/lock.ts:1, 15-20`); path joins by string `${root}/config` (`src/lib/paths.ts:50-71`); `crontab` (`bootstrap.sh:249-270`). Zero occurrences of `win32|windows|junction` in `src/`.
19. **Symlink-hostile behavior.** No fallback: `Deno.symlink` failure propagates as `ExtractFailed` exit 3 (`src/sync.ts:255-258`). Conversely it is *defensive against hostile symlinks* in the source: tarballs are walked and any symlink resolving outside staging aborts extraction (`src/lib/fs-utils.ts:119-155`); local-source symlinks are skipped, not dereferenced (`src/lib/local-source.ts:36-42, 64-67`).
20. **Adopt.** The five-way target classifier + quarantine-never-delete + TTL (Q7/Q9); managed marker block with strict-parse + relaxed-repair (Q13/Q15); per-file hash map for drift + fast path (Q11/Q13); `--check` exit-code taxonomy (0/4/5) and `--dry-run` planned-action vocabulary (`would-symlink/would-refresh/would-quarantine`); `ToolProfile{sourceRoot, categories[{sourcePath, projectPath}], gitignoreRoots, quarantineDir, marker}` as the shape of a *harness profile* (`src/types.ts:71-84`); escaping-symlink rejection (Q19); "own-ness" test by link target prefix; explicit resolution order for config (flag > existing > committed file > user defaults > prompt > error, `src/enroll.ts:6-22`).
21. **Explicitly NOT copy, and why.** (a) Push-from-remote model with cron + PAT + staging under `~/.config` — AgentConcord's truth lives *in the repo*, so there is no staging indirection to protect and no hourly tick. (b) Absolute-path symlinks into a per-machine cache: unshareable, uncommittable, break on clone; we need relative in-repo symlinks or generated files. (c) Read-only chmod of the source: hostile to editing-in-place, which is exactly the workflow we support. (d) Byte-identical content per tool with hard-coded categories and *no* format translation — cannot handle `.cursor/rules/*.mdc`, `copilot-instructions.md`, `settings.json` merges, or agent frontmatter differences. (e) Registry keyed by `sha1(realpath)` — fragile under moves/worktrees. (f) Content-blind: no frontmatter parsing, no name-collision detection, no staleness/duplicate analysis. (g) gitignore-everything: our projections are usually meant to be committed so teammates and CI see them.

## 5. Patterns across the four sources

**P1. Nobody does the whole AgentConcord loop.** wshobson = one-way *projection* from a marketplace tree; agents-skills-sync = one-way *distribution* of opaque bytes into projects; Adobe = *prescriptive content architecture* + LLM-run audits. None ingests an arbitrary repo's existing harness, audits it, converges, projects, and drift-checks in one tool. The gap is real.

**P2. One authored file, pointers everywhere — three different pointer mechanisms.** wshobson: `CLAUDE.md -> AGENTS.md` symlink (tested). Adobe: `CLAUDE.md` = 3-line `@AGENTS.md @INVARIANTS.md` import shim + `.claude/skills/<n>` relative symlink to `.agents/skills/<n>`; direction rule "AGENTS.md must hold the real content; never the reverse". agents-skills-sync: absolute symlinks into a per-machine cache. Only Adobe states the *direction* invariant and detects the reversed case (`scan.sh reversed-symlink`).

**P3. Format translation exists in exactly one place (wshobson) and is lossy in known ways.** Tools→permissions (tri-state), model aliases, `$ARGUMENTS→{{args}}`, body splitting at Codex's 8 KB cap, prose rewriting by regex — all driven by a code-level capability matrix. Hooks/MCP/settings are dropped silently by every adapter; Adobe's only translation is `applyTo` → skill `description` then delete. agents-skills-sync translates nothing (separate `.claude/` and `.codex/` subtrees in the content repo).

**P4. "Own-ness" is always a pointer test, never a marker.** agents-skills-sync: `readlink(target).startsWith(stagingDir)`; wshobson installers: `dst.resolve() == src` / target inside generated root. No source emits "generated — do not edit" banners or a state/lock file with content hashes. Consequence in wshobson: a user edit to `.opencode/agents/x.md` is silently clobbered by the next `make generate`.

**P5. Never-destroy shows up as three different postures.** agents-skills-sync: *quarantine* (rename to `<dir>/.claude-config-collisions/<name>.<ts>`, 30-day TTL, kept on unenroll). wshobson installers: *refuse* real files, replace only foreign symlinks with `--force`; generator: *overwrite*. Adobe: *migrate then delete* with the human rule "Never delete a file before confirming its content is preserved". Only the quarantine gives a rescue window without a human in the loop.

**P6. Drift detection maturity: hashes > CI regenerate gate > mtime > human checklist.** agents-skills-sync: per-file SHA-256 map + fast path + `--check` exit 4/5 + strict marker-block parse. wshobson: CI "regenerate, `git status --porcelain` must be empty" (strong) but gardener staleness by **mtime** (weak; breaks on fresh clones). Adobe: monthly/quarterly prompts run by the agent itself, twice, then reconciled.

**P7. Real-harness validation is thin everywhere.** wshobson is best: `opencode agent list`, `agy plugin validate`, `codex doctor`, `gh skill install --from-local` in CI — but `claude --version` only, and Cursor/Copilot have no round-trip. agents-skills-sync never invokes any CLI. Adobe's behavioral tests are prompts ("recite top-3 invariants without re-reading"). None tests that a *skill actually fires* on a trigger phrase in the real tool.

**P8. Windows is a known, unhandled hazard.** All three code paths assume POSIX symlinks (`Deno.symlink`, `Path.symlink_to`, git `core.symlinks`). agents-skills-sync additionally shells to `df`/`tar`/`crontab`/`flock`. Adobe documents the failure mode (symlink checked out as a text file → "Claude Code silently discovers nothing") and the workaround (Developer Mode + `core.symlinks true`, or `@` command shim). No source has a copy-with-provenance fallback.

**P9. Explicit category/path mapping beats auto-discovery for safety.** agents-skills-sync's `ToolProfile{sourceRoot, categories[{sourcePath, projectPath}], gitignoreRoots, quarantineDir, marker}` is the cleanest declarative shape seen; Codex being *multi-rooted* (`.agents/skills` + `.codex/rules`) is the case that justifies it. Its weakness — categories hard-coded in the engine — is a config-surface problem, not a design flaw.

**P10. Generic content is the dominant failure mode of collections.** wshobson: 194/202 "You are…" openers, one six-heading template on ~60% of agents, ~70 of 202 agent files are copies, ~70% generic personas. Adobe names the smell directly: "Generic content is a signal the harness was templated rather than crafted" and "Skills … create per recurring task type only". AgentConcord's "fewer, better, domain-shaped" goal should be a *lint* (template-skeleton detection, same-body-different-name detection, repo-grounding check: does the skill reference paths/commands that exist?).

**P11. Committed vs ignored is a per-artifact decision that must be explicit.** wshobson commits pointer registries and ignores transformed trees; agents-skills-sync ignores everything via managed blocks; Adobe commits everything (symlinks included). A per-repo tool needs a declared policy per projection with a state file so CI can verify either choice.

**P12. Every finding should carry a fix.** wshobson `Finding.remediation` and Adobe's rot/critical/quick-fix/larger/token taxonomy with a noise filter ("discard … speculative, without a specific file:line") are the two best output contracts; agents-skills-sync's exit-code taxonomy (0/1/2/3/4/5) and sentinel transitions are the best *machine* contract.

### Open verification items for AgentConcord (from this study)
1. Claude Code: does it read `AGENTS.md` natively today? Does it discover `.claude/skills/<n>` when that is a symlink (dir) — on macOS, Linux, Windows? Does `@import` in CLAUDE.md follow relative paths and nested imports? (Adobe C1–C4.)
2. Codex: exact scan roots — `.agents/skills/` vs `.codex/skills/`; `AGENTS.md` size cap (wshobson enforces 150 lines / Adobe none); `sandbox_mode` enum.
3. Copilot: `.github/copilot-instructions.md` + `.github/instructions/*.md` `applyTo` vs `.agents/skills/` vs `.copilot/` — which are read from a repo vs from `~/.copilot` (wshobson installs to home; Adobe says repo `.agents/skills/`).
4. Cursor: `.cursor/rules/*.mdc` frontmatter keys actually honored (wshobson's validator calls `agentRequested:, mode:, tags:` "folklore"); whether Cursor reads `.claude/` dirs at all (wshobson claims, without a `.claude/` dir to prove it).
5. OpenCode / Antigravity / Gemini CLI: confirm the file layouts wshobson emits (`.opencode/{agents,commands,skills}`, `opencode.json`; `~/.gemini/antigravity-cli/plugins`) — these have real-CLI smoke tests and are the most trustworthy claims in the whole study.
