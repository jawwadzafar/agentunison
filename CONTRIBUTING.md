# Contributing to AgentUnison

## Where things are
- `docs/TASKS.md` — the task board. Every task has goal, scope, steps, acceptance, validation
  commands and a verification recipe id.
- `docs/VERIFICATION.md` — the recipes (`V-01…V-11`): exact command → expected result → meaning of failure.
- `AGENTS.md` — rules for humans and coding agents working here (short, canonical; `CLAUDE.md` is a shim).
- `dev_docs/2026-09-04/` — research with sources/revisions, design 001–008, the design review, PROGRESS.
- `docs/adr/` — decisions (ADR-0001 language & packaging).

## Picking up a task
1. Take an `OPEN` task from `docs/TASKS.md` whose blockers are done. Branch `t-<nn>-<kebab>`.
2. Read the task's scope files and the relevant design section (003–006) before coding.
3. Tests first when behavior changes: add a fixture assertion (`test/messy.test.ts`, `test/safety.test.ts`)
   or a unit test (`test/unit.test.ts`). The messy fixture is generated by `test/fixtures/make-messy.sh`.
4. Implement. Rules that are not negotiable:
   - `apply` is the only writer; every write goes through the plan; `lstat` before writing; never through a symlink.
   - No deletion without an explicit `DELETE` action approved with `--allow-delete`; displaced content is quarantined.
   - Only ledgered paths are modified/removed. Foreign files are reported, never touched.
   - A compatibility fact used in code must exist in `matrix/<harness>.yaml` with `evidence` and `checkedOn`.
   - Erasable TypeScript only; relative imports end in `.ts`; runtime dependency is `yaml` only.
   - Byte-identical second run: no timestamps or platform facts in committed files.
5. Validate: `npm run typecheck && npm test`, then the task's `V-nn` recipe. Paste both outputs in the PR.
6. Update `docs/TASKS.md` (status) and `dev_docs/<date>/agentunison/PROGRESS.md` (what changed, what was verified, gaps).

## Definition of done
- Acceptance criteria in the task met, with evidence (command output) in the PR.
- `npm test` green locally; CI green on ubuntu/macos/windows.
- `node bin/agentunison.js verify` on this repository still passes (dogfood).
- No new claim in `README.md` without a test or a recipe that proves it.
- If a harness fact changed: matrix updated with new `versionsVerified`/`checkedOn`, and the manual probe
  from `docs/VERIFICATION.md` §V-06 recorded in PROGRESS.

## Changing the matrix
Facts are data, not code. To change one: run the corresponding manual probe (V-06), update `value`,
`evidence`, `checkedOn`, `platforms`, `versionsVerified`, add a `note:` with what you observed, run
`npm test` (the loader validates the schema), and open a PR titled `matrix: <harness> <version>`.

## Commit and PR conventions
- Conventional prefixes: `feat:`, `fix:`, `matrix:`, `docs:`, `test:`, `chore:`.
- One task per PR where possible; reference the task id (`T-04`).
- No AI attribution footers in commits or PR text.
